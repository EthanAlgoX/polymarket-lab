# 功能逻辑与修复审计

审计日期：**2026-10-03（Asia/Shanghai）**。本文对应仓库当前实现，区分运行功能、数学估算和后续研究方向。本次离线测试、公开接口和 macOS 浏览器验证见第 11 节；网络结果仅描述本次检查时的状态。

## 1. 项目提供什么

Polymarket Lab 是本地运行的公开数据研究台。它直接读取 Polymarket 官方 Gamma、CLOB 和 Market WebSocket，提供市场目录、分类筛选、盘口核验、完整集成本估算、有限样本候选扫描、历史与模拟记录。浏览器通过本地 FastAPI 获取数据。

项目不连接钱包、不签名、不提交订单、不划转资金。保存模拟记录只是保存当时估算及其输入；不存在真实成交、持仓管理、自动结算或已实现收益。交易空间和开源参考页提供有依据的研究材料，但不会自动判断天气、体育或加密预测具有统计优势。

## 2. 页面和用户流程

九个导航入口共用侧边栏；桌面保留侧栏，窄屏使用可横向滚动的导航，并使当前入口可见。

| 页面 | 实际功能 | 数据与刷新 |
| --- | --- | --- |
| `/#markets` 市场目录 | 六类行业筛选、原文搜索、最低流动性、四种排序、每页 40 条；显示覆盖范围、目录版本、筛选统计、预选与实际扫描分布 | 本地目录快照；可见时每 15 秒重新读取，完整目录遍历另有周期 |
| 目录内“核验盘口”抽屉 | 先核对最新 Gamma 开盘状态及原始结果/token顺序，再获取真实盘口；可修改每腿数量、其他成本；查看规则及原始市场链接 | 当前市场元数据和 REST `/books`；打开且可见时每 5 秒读取 |
| `/#strategies` 交易空间 | 按行业显示候选信号、必需数据、失效场景、下一步验证和来源 | 仓库中的研究材料，不是实时预测引擎 |
| `/#opensource` 开源参考 | 高星项目、高星未归档、全部参考三种筛选；按 star 排序；显示维护状态、许可核验、采用决定和源码依据 | `app/research.json` 的有日期快照，不自动更新 GitHub star |
| `/opportunities` 盘口扫描 | 仅显示通过全部候选门槛的当前 Yes/No 样本；列表搜索、详情、保存模拟 | 有限扫描样本；可见时每 5 秒读取 |
| `/markets/{market_id}` 扫描详情 | 原始市场与 token、展示盘口、盘口质量、成本估算及用于此次计算的独立 REST 卖盘 | 展示书可以由 WS 更新；计算书和计算时间另外显示 |
| `/monitor` 运行监控 | Gamma/CLOB/WS/地区/数据库状态、运行时间、请求/重试/限流计数、当前候选、模拟数量与估算合计 | 可见时每 5 秒读取；候选数量重新检查实时有效性 |
| `/paper-trades` 模拟记录 | 保存过的模拟摘要、每页 100 条、前后翻页、完整 CSV 导出 | 本地数据库；手动刷新，历史不自动重算 |
| `/history` 信号历史 | 曾通过门槛的快照、首次/最近发现、最大差额/收益率/数量和信号状态；每页 100 条 | 本地数据库；当前报价须回到扫描器核验 |
| `/settings` 扫描参数 | 编辑五个允许的门槛/缓冲参数，提示未保存/保存中/失败；防止重复保存 | 参数先持久化、后原子替换；下一次成功盘口计算使用新值 |
| `/logs` 运行日志 | 本地事件时间、级别、来源、事件和脱敏说明；按级别筛选最近记录 | 默认最近 100 条，可见时每 5 秒读取 |

抽屉支持 Escape 关闭、焦点限制和关闭后返回触发位置。筛选和抽屉请求使用序列号、取消及超时：较晚返回的旧请求不能覆盖新市场或新筛选。刷新失败保留旧展示并明确标识失败，不继续给出新的正差额判断。页面隐藏时暂停上述自动读取；后台采集不因此停止。

“刷新数据”读取服务器当前快照，不强制重新遍历整个 Gamma 目录。目录流动性是 Gamma 汇总指标，展示价格是目录参考价，两者都不能替代可成交深度。

## 3. 启动、后台任务和关闭

1. 启动入口读取并校验 `PMS_` 环境配置及忽略的本地 `.env`，创建 `data/`、`logs/` 和 SQLite 表。
2. 旧的 `active` 历史信号在启动时标为 `disappeared`，等待新的公开盘口核验。数据库中保存的五个可编辑参数与有效环境默认值合并后整组校验；非法持久参数不会覆盖有效环境值，错误记录不含其原值。
3. 若 `PMS_ENABLE_LIVE_SCANNER=false`，不启动 Polymarket 后台采集；本地页面、数据库和可选翻译服务仍可以启动。
4. 在线模式先检查地区状态、读取热门/新建/分类事件样本、建立有界扫描集合并读取初始盘口。初始请求可能延迟服务就绪；完整目录遍历随后在后台继续。
5. 后台包含目录遍历、市场状态核验、REST 盘口扫描、WS 连接。完整目录每轮结束后等待 600 秒；市场刷新默认 60 秒，盘口轮询默认 5 秒。网络耗时意味着这些是等待间隔，不保证端到端固定延迟。
6. 市场刷新、盘口发布、参数修改和保存模拟共用刷新锁，防止新市场与旧 token 书、新参数与旧结果混用。计算和数据库异常会清除候选并记录错误；周期任务继续等待下一次恢复。
7. 关闭时停止翻译 worker、取消并等待采集任务、关闭 HTTP/WS/SQLite。初始化或启动异常也进入清理路径。

`/health` 检查本地数据库，正常为 200，异常为 503。健康检查成功只说明本地服务与数据库可用；Polymarket 数据链路、覆盖和行情新鲜度需看运行监控及各自时间字段。

## 4. 目录、选样和最新市场状态

Gamma `/events/keyset` 是目录来源。启动先取得热门、最新及分类种子，再按游标遍历最多 100 页、每页 100 个事件。一个事件可能有多个子市场，因此 10,000 个事件不等于 10,000 个市场。

目录只纳入 active、未 closed、acceptingOrders、enableOrderBook 的市场；结果与 token 必须按原数组位置对应。行业按事件标签归入体育、天气、加密、经济/金融、政治、其他之一。空标签、非法价格和异常数值不能导致 JSON 序列化失败；超过展示范围的金额记录被省略并计入 `invalidRecords`，价格缺失保留原结果位置。

| 覆盖状态 | 含义 |
| --- | --- |
| `loading` | 尚未取得可用目录 |
| `sample` | 初始样本，尚未完成遍历 |
| `paginated` | 此轮接口分页正常结束，目录以本轮实际遍历为准 |
| `capped` | 到达接口或本地上限，可能保留本轮种子补充，覆盖有界 |
| `partial` | 遍历中断，保留已发布数据并报告错误 |

遍历在草稿中进行，然后发布一份带 `revision` 的目录、原始映射和预计算行业汇总。一次 `/api/catalog` 响应使用同一个版本。失败时保留上一份数据和其更新时间；`coverage` 描述当前遍历结果，`dataCoverage` 描述保留数据的实际来源。正常分页完成会移除只在种子中出现、此后已退出开盘集合的市场；重复游标、不合理的下一页或非法分页标志不会被误报为完成。

扫描器仅选择 Yes/No 二元市场。先按流动性与**总成交量**门槛过滤，再最多进行八轮行业轮流分配，最后按 24h 成交量、流动性和 ID 补齐，名额由 `PMS_MAX_MARKETS` 控制（代码默认 40；本地可以配置为 80）。选样不是覆盖全平台的套利证明。

每次复用目录样本前，再通过 Gamma `/markets?id=...` 每批最多 100 个核验当前状态、费率及原始映射。关闭、暂停、缺失或不达门槛的市场不进入当前扫描。原条件或结果/token顺序变化会暂停核验，不能借用陈旧映射。目录不可用时，`/markets/keyset` 提供新鲜的有限样本，不重复请求。

`scannerSelection.selectedTotal/categoryCounts` 是目录预选；`verification.verifiedTotal/categoryCounts` 是最新核验后实际扫描数，另含来源目录版本、核验时间与失败状态。核验失败时保留旧展示但清除计算/候选，新的书不能绕过失败的元数据状态重新激活旧机会。

WS 的 `market_resolved` 只有 ID、condition、结果 token 与获胜 token 严格匹配已知市场才生效。已结算市场立即退出目录与扫描，在进程内保留终态记录，正在遍历的草稿、失败回退及陈旧 Gamma 响应都不能把它复活。

## 5. REST、WS、盘口身份和新鲜度

CLOB `POST /books` 是公开批量读取；请求按 token 去重，每批最多 500 个。只接收本批请求的 token，不接收无关返回书。每个结果对应自己的真实资产；不共用两腿书，不因标题或翻译重新匹配 token。

运行时维护两份来源：

- `books`：展示书，可以来自 REST 或 WS 完整 `book` 消息。未知/旧订阅 token 被忽略；较旧或无效时间书不能覆盖已知更新的展示书。
- `calculation_books`：与计算结果共同发布的独立 REST 批次，WS 不修改它。详情中的 `calculation_orderbooks`、`calculation_as_of` 与持久化 audit 对应这份输入。

WS 每十秒按固定时间发送 `PING`，即使不断收到消息也不会取消心跳；接收 `PONG`，订阅变化会重新连接。去重针对完整规范化消息，保留同一毫秒不同内容；缓存有界且新连接清空，避免漏掉初始书。单条处理异常不丢弃后续合法消息，也不会把未成功处理的帧永久当作重复。当前没有把 `price_change` 增量合并为用于计算的行情。

书时间是 epoch 毫秒。使用 Decimal 精确检查，缺失、非法、非有限、非正及超过一秒未来偏差都视为未知。两腿使用更旧的来源时间；当前有效性同时比较真实来源年龄和发布后累计年龄，因此本地时钟回拨也不能把未知时间当新鲜。

展示指标包括最佳买卖、价差/基点、首档数量、失衡、首档加权价，以及各自最佳价格附近 0.02 的股数和抵押金额。空书、单边、交叉或异常书的质量标签与 stale 标签分开。盘口指标描述当前流动性，不是胜率、预测优势或保证利润。

## 6. 完整集成本和候选门槛

金融计算始终使用 `Decimal`。同一个二元条件，两腿各买相同股数：

1. 卖盘按价格由低到高消耗，确定两腿共同可取得数量，再按该共同数量计算各档成本。不会拿最佳价乘以整笔数量，也不会让两腿数量不等。
2. 理论完整集回收是共同数量乘以每股 1。毛差额为回收减两腿买入成本。
3. 已知费用按每个实际消耗价格档估算 `quantity × rate × price × (1 − price)`，四舍五入保留五位小数后相加。费用不会由行业名称猜测，也不把未知费用设为零。
4. 净差额扣除手续费、按买入成本计算的滑点/安全缓冲和固定其他成本。收益率分母包含上述总预算，避免漏计资金占用。
5. 两腿不能是同一个 token；存在的书 condition 必须相同且匹配已知市场。非法价格/数量、交叉书或不可表示的算术产生明确无效状态，暂停净差判断。

当前流水线使用最新 Gamma `feesEnabled` / `feeSchedule`。明确免手续费为已知零；有费用时需核实有限非负费率及支持的指数 1。客户端另保留官方 `/clob-markets/{condition_id}` 费率 helper；未知或其他指数仍返回 `FEE_UNKNOWN`，不隐式套用指数 1。

候选必须同时满足：最新市场状态可扫描、Gamma/CLOB 链路正常、两份 REST 来源书齐全且身份一致、费用已知、时间有效且未超过门槛、共同数量达到目标和最低数量、两腿最小订单数量明确且满足、无 partial fill、净差额为正并达到最低金额与最低总预算收益率。

常见暂停状态包括 `FEE_UNKNOWN`、`MIN_ORDER_UNKNOWN`、`BELOW_MIN_ORDER`、`STALE`、`PARTIAL`、`NO_ASKS`、`INVALID_PAIR`、`INVALID_BOOK`、`CROSSED_BOOK`、`INVALID_CALCULATION`。结构错误不会被次要 stale/min-size 标签覆盖。持有结果随时间变旧时，API 的显示副本会标 `STALE` 并更新年龄，原持有计算保持不变。`VALID` 仅表示完整的数学估算，`is_candidate` 还需要全部来源、状态、数量与净差/收益率门槛；页面分别显示这两个判断。

目录抽屉可以展示队名、Up/Down 等同条件二元结果的成本估算，保留原始显示顺序；超过两个结果只展示各结果书，未实现多结果完整集。抽屉中的正差额描述该次估算，不自动进入有限扫描器，也不能直接保存为真实交易。

## 7. 参数、历史、模拟记录与导出

参数页可编辑：最低净差额 0–1000、最低预算收益率 0–1、目标数量大于 0 且不超过 100000、滑点率与安全率各 0–0.25。其余端点、刷新频率、样本数、最低流动性/总成交量、最低可执行数量、默认其他成本和时间门槛属于 `PMS_` 启动配置。收益率和缓冲率输入使用小数，不是百分数文本。

五参数统一校验，以一个数据库事务保存，并在刷新锁内替换运行时配置，不修改模块共享的环境默认对象。写入失败保留旧配置和结果。保存成功清空旧计算、让旧 active 历史失效，等待新参数下的盘口计算。服务重启会恢复合法持久参数。

有效扫描信号按完整快照与计算输入指纹保存，更新首次/最近时间及估算范围。新批次、缺书、市场变化、请求或计算失败、参数变化和服务重启会使不再有效的信号标为 `disappeared`；同一指纹再次通过门槛时可以恢复 `active`。历史 active 反映最近一次后台核验，不替代当前 `/api/opportunities` 的动态门槛检查。

保存模拟在同一刷新锁内重新检查来源与门槛，不能在参数更新或报价过期后保存原候选。无来源/失效返回 409。记录包含 `details.audit`：来源、计算时间、原始市场/结果/token、参数、实际两腿 REST 书。历史与模拟列表返回轻量摘要；只读详情 API 返回完整 audit，避免每页读取大量完整盘口。旧记录可能没有新增 audit，不能追补为当时已保存的输入。

模拟汇总仅累计 `SUCCESS` 的估算净差额，仍不是已实现收益；重复观察同一个候选可以产生多条模拟，因此汇总也不是账户 P&L。前端阻止同一按钮的并发重复保存。

CSV 导出遍历全部已保存记录，不受列表 100/500 条分页限制；使用流式分块、明确列名和 UTF-8 BOM。市场标题等文本若以 `= + - @` 开头会加单引号转义，阻止表格公式执行；金额等经 Decimal 生成的数值保留数值格式。空库也导出表头。搜索和 CSV 保留官方原文，不写入机翻文案。

## 8. 中文/英文与 DeepSeek

语言偏好保存在浏览器，默认中文；English 恢复官方市场字段原文。DOM 观察会对新出现、变化及展开可见规则自动处理，不预先翻译整个目录。常用结果可以本地直译，无需提供商请求；可见英文文本批量提交到本地翻译 API。

后端只允许已服务过的公开市场字段，或它们确定的无损长规则分段。任意用户字符串不能借此消费 API 额度。译文持久缓存按模型、提示版本、中文目标、完整原文哈希隔离；相同原文重用，新原文自动生成新缓存条目。

翻译仅访问官方 DeepSeek HTTPS，密钥只从后端命名环境变量或忽略的本地 `.env` 读取。默认 `deepseek-flash`（DeepSeek V4.1 Flash；最便宜官方模型的既有核验日期为 2026-10-02），关闭思考；有限纠正重试用同一模型，不自动升级。校验数字出现次数、受保护符号、URL、结果 ID 和完整响应；不合格、缺密钥、余额/网络/限流错误都显示原因并保留原文。

翻译 API 每次 1–80 条、单条不超过 20000 字符、合计不超过 100000 字符；后台队列和 worker 有界。前端显式重试，避免失败时无限付费循环。机器校验不证明每个否定、期限和结算条件的语义完全正确；涉及规则时可切回原文核对。翻译不修改价格、数量、ID、结果顺序、结算标识或计算输入。

macOS `start-local.command` 使用项目 `.venv`，首次选择 Python ≥3.11 并安装锁定依赖；缺少继承的翻译环境时加载用户 zsh。`python -m app` 统一读取校验后的 `PMS_HOST/PMS_PORT`，Windows `run.bat` 也使用它；`install.bat` 负责安装、数据库与离线测试，执行失败即停止。Docker/Compose 提供独立 Python 服务和数据/log volume；默认将服务端口仅映射到宿主机 127.0.0.1。

手动 `uvicorn --host/--port` 的命令行值由调用者决定，不能期望 `PMS_PORT` 覆盖显式 CLI 参数。`.env`、`.venv`、数据库、日志和翻译缓存保持本地，不提交；真实项目许可和上游来源在 [UPSTREAM.txt](../UPSTREAM.txt)。

## 10. 本次确认并修复的问题

| 原触发条件 | 后果 | 修复 |
| --- | --- | --- |
| 市场刷新与等待中的盘口/参数/模拟交错 | 旧书、新市场或旧参数混用 | 共享刷新锁；独立 REST 输入与结果共同发布 |
| 计算异常或错误事件写库失败 | 后台循环退出或旧候选残留 | 扩大保护区、失效候选、周期恢复、错误记录尽力而为 |
| 市场更新后旧 token/结果缓存未清 | 展示和旧结果残留 | 按当前订阅剔除书，清旧计算与费用原因 |
| 完整分页结束仍混入 seed-only 行 | 已退出开盘集合的市场残留 | 完整遍历以实际遍历 ID 为准；上限覆盖明确标注 |
| 重新选样却不请求当前市场状态 | 目录旧 closed/accepting/费率冒充最新 | 每个有界样本批量核验最新 Gamma；失败暂停候选 |
| WS resolved 被忽略，或旧草稿/回退复活终态 | 已结算市场继续扫描 | 严格生命周期匹配、终态记录和目录/缓存移除 |
| Gamma fallback 忽略终止标志或重复游标 | 多请求、重复样本、完成状态失真 | 校验终止/游标/schema；拒绝异常分页 |
| 常态 WS 消息持续到达 | 心跳永不发送 | 固定十秒心跳期限，与普通消息无关 |
| 同时戳不同消息或未成功处理消息 | 漏更新、失败帧无法重试 | 全消息去重、处理成功后入缓存、单帧隔离 |
| 未请求/旧订阅/更旧时间的书 | 无关或旧书覆盖当前显示 | token身份过滤及来源时间顺序检查 |
| 不同市场两腿、交叉书、巨量有限 Decimal | 错误正差额或计算异常 | 条件匹配、结构验证、极端算术失效状态 |
| 缺最小订单或非法/未来时间 | 无依据却认定可成交 | `MIN_ORDER_UNKNOWN` / `STALE` 严格阻止候选 |
| 费率缺指数仍默认套用 1 | 未知费用被误作已核实 | 缺失/null/非法/不支持指数一律未知；核验与计算不猜费率 |
| 时钟回拨或持有结果自然过期 | 旧 VALID 继续显示通过 | 重查 REST 来源年龄；显示副本转 STALE |
| 参数落库与运行内存/重启不一致 | 页面值与真正计算值不同 | 统一整组校验、单事务、原子配置、启动恢复 |
| 指纹遗漏真实输入或历史不失效 | 不同假设合并、active 永远留存 | 完整输入指纹、失效/重新激活、保存 audit |
| 列表分页/导出限制、公式文本或 SQLite 时区缺失 | 记录漏读、导出截断/公式执行、时间错位 | 列表翻页、完整流式 CSV、文本转义、统一 UTC 字符串 |
| 并发筛选/详情或重试乱序、页面错误仍显示正常 | 旧数据覆盖新选择、误导新鲜度 | 请求序列/取消/超时、失败标签、刷新和保存并发保护 |
| 非法参数、健康检查、运行入口不一致 | 参数绕过、失败仍显示健康、端口设置不生效 | 服务端校验、数据库健康 503、统一运行入口 |
| 译文改数字/符号/URL或失败循环 | 内容变化或无界消耗 | 受保护字段校验、缓存隔离、受限廉价重试 |

## 12. 当前实际限制与后续选择

- 目录是周期、有上限的发现快照；市场随时变化，有界扫描与其他目录市场之间不能互相推出有无套利。静默但很久未更新来源时间的书也会被严格时间门槛暂停。
- 两腿成交没有执行原子性；手续费和成本是公开输入下的估算，固定其他成本尚未实测链上合并/结算开销。项目没有实现真实执行。
- 仅扫描 Yes/No 二元条件；多结果完整集、跨事件逻辑套利、跨平台套利、自动做市和预测模型未实现。天气观测、体育赔率、外部参考价格也没有接入。
- 没有持续保存全部市场的全部历史盘口，也没有完整回测/回放。数据库中的盘口快照/日统计表结构不等于已经运行的归档与统计任务；本次仅为有效信号和模拟保存必要 audit。
- 历史保留和翻译缓存没有自动删除策略；长时间运行可能增长，未来如需保留期限，应先决定哪些研究记录应保留，不能擅自删除。
- 搜索以原文为主，界面固定操作文案以中文为主；语言切换针对市场字段。开源研究材料和费用依据有核验日期，需要新的证据才更新。
- 翻译的语义准确性不能由数字和符号校验完全证明；原文仍是结算依据。额度消耗由实际新文本与提供商账户决定。
- 本地只读工具没有多用户身份/授权设计。Docker/Windows 提供启动配置，但跨平台运行结论只能在对应环境实际验证后给出。

这些是当前实现边界；没有为了本次技术缺陷修复而必须先确认的需求歧义。后续若扩展执行、预测数据源、长期历史留存或多用户部署，应分别定义目标与验收标准。
